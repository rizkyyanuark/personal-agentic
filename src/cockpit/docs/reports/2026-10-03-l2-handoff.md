# Handoff L2: pemisahan status dan suasana

Tanggal: 3 Oktober 2026 (WIB).
Target: preview lokal http://127.0.0.1:8099.
Status: implementasi lokal siap; penerimaan browser dan review pemilik belum dilakukan.

## Lingkup yang sudah diterapkan

Model `office-presentation.js` mempertahankan fakta state/task publik, pose
lokal berlabel Suasana ilustratif, dan uraian role statis berlabel Deskripsi
peran pada jalur berbeda. Kartu tidak membaca `agent.activity` atau menganggap
event riwayat sebagai tugas aktif. Copy awal tidak mengklaim karakter sedang
santai atau Orion sedang memantau tugas.

Gate bersama mengharuskan kontrak publik valid, koneksi live/empty, stale tepat
nol, dan tab terlihat. Hide/show membutuhkan pembacaan baru. Reduced motion
membekukan gerak, bukan status API atau sofa statis pada data segar. Pose, TV,
dan animasi monitor memakai gate yang sama dalam loop yang sudah ada.

Bubble event berlabel Riwayat publik dan memiliki jenis eksplisit. Perubahan
status/gate membatalkan bubble/timer yang tidak sesuai. Stop polling membatalkan
request aktif; respons lama setelah hide atau Back tidak boleh mengganti state
baru. Teardown melepas model, timer, dan listener label; BFCache menjaga objek
bisa dipakai kembali tetapi menunggu pembacaan baru.

Tidak ada perubahan CSS, denah, kamera, font, aset, dependency, kontrak/server,
ledger, atau runtime agent. L3 jalur/kegiatan baru, L4 dialog/bubble kerja di
scene, L5 kuota/penempatan, serta game/gitar belum diimplementasikan. Pada L2,
scene hanya melaporkan pose yang sudah benar-benar ada: meja, sofa, dan papan.

## Arahan untuk kolega, setelah implementasi

Uji preview 8099, bukan produksi. Jangan ubah kode produk, ledger, role runtime,
worker, atau vault. Keadaan uji dibuat dengan intersepsi respons `/api/state`
hanya di browser; semua fixture harus memenuhi kontrak lima role dan jelas
dicatat sebagai fixture, bukan aktivitas nyata. Lepas intersepsi setelah uji.

1. Pastikan HTML memuat JS `index-D6Y73iqy.js` dan CSS `index-DCvnlAGa.css`.
   Catat hash yang tersaji, bukan sekadar tanggal atau port. Jangan menilai
   screenshot dari build lama sebagai hasil L2.
2. Jalankan `npm run check` dengan build terisolasi lalu
   `COCKPIT_URL=http://127.0.0.1:8099 npm run test:e2e`. Laporkan exit code
   nyata dan blocker QA lama terpisah; jangan menghapus assertion agar hijau.
3. Periksa 320, 390, 768, 1024, dan 1440 px, serta resize antar-breakpoint.
   Pastikan layout/card/pill/dock L1 tetap sama dan copy aktivitas berlabel bisa
   dibaca lewat kartu/title/label aksesibilitas. Zoom/native/BFCache yang belum
   terbukti tetap dicatat unverified, bukan diasumsikan lulus.
4. Fixture live dan empty dengan stale nol: siaga tetap state API `siaga`,
   pill Istirahat. Subteks menyebut pose aktual dengan Suasana ilustratif.
   Orion tidak memiliki meja. Tidak ada kegiatan baru kopi/baca/roaming pada L2.
5. Ganti satu role bekerja, menunggu keputusan, gagal, lalu siaga. Status/task
   DOM berubah pada respons berikutnya, tidak tertunda pose. Saat bekerja,
   subteks Deskripsi peran adalah uraian statis, bukan tujuan tugas atau kode
   privat. Menunggu tetap pill pendek dengan makna penuh aksesibilitas.
6. Naikkan queue.stale menjadi angka positif tanpa mengganti state role.
   Suasana/typing/TV berulang berhenti, karakter memakai anchor desk/HQ,
   subteks menunggu data segar, dan state API tetap utuh. Pulihkan stale nol
   melalui respons valid untuk mengaktifkan pose lokal kembali.
7. Uji jaringan gagal dan HTTP 503 dengan body publik connection error valid.
   Offline berbeda dari error. Kartu tidak mempertahankan tugas aktif atau
   narasi lounge; bubble hilang. Pulihkan respons live valid dan cek recovery.
   Feed tidak perlu tetap berisi delapan event ketika offline; itu bukan klaim L2.
8. Intersep satu request menjadi tertunda, sembunyikan tab, lalu tampilkan lagi.
   Request lama harus dibatalkan/diabaikan. Suasana tidak aktif kembali hanya
   dari snapshot sebelum hide; harus ada pembacaan valid baru. Pastikan tidak
   ada interval polling ganda atau respons lama menimpa status baru.
9. Aktifkan reduced motion saat sofa terisi. Pose sofa tetap statis, frame
   balapan tidak bergerak, typing dan gerak monitor berhenti. Polling/status
   serta uraian role statis masih diperbarui. Mematikan reduced motion tidak
   boleh mengaktifkan aktivitas bila koneksi/freshness belum valid.
10. Poll pertama dengan feed lama tidak memunculkan event sebagai pekerjaan.
    Pada fixture event baru, bubble berjenis event dan teks Riwayat publik.
    Ubah status role, stale, offline, atau hide saat bubble aktif; bubble dan
    timer lama harus hilang, tidak muncul kembali. Dialog fiksi/kuota kerja
    bukan kriteria L2 karena baru dikerjakan pada L4/L5.
11. Uji Back yang benar-benar memulihkan halaman. Catat `pageshow.persisted`
    beserta state polling/label. Bila BFCache tidak terjadi, tulis unverified
    dan bedakan dari navigasi ulang. Jangan menyimpulkan dari array log kosong.
12. Catat console/pageerror, request yang gagal, fixture dan urutan transisi,
    screenshot sebelum/sesudah, semua PASS/FAIL/unverified, serta langkah
    reproduksi. Kembalikan ke data nyata setelah uji dan buat satu laporan L2.

Laporan uji bukan izin deployment. Check menyeluruh, verifikasi browser,
perbandingan visual, dan persetujuan pemilik tetap diperlukan.

Catatan kompatibilitas suite lama: `tests/e2e/office-experience.mjs` membuat
fixture default dengan `queue.stale: 2`, tetapi bagian `assertTVModes` lama
mengharapkan work-screen dan balapan bergerak. Setelah L2 kedua ekspektasi itu
memerlukan fixture segar dengan stale nol. Jangan mengubah gate produk atau
melemahkan assertion untuk meloloskan fixture usang; pisahkan kasus data segar
dan stale jika suite tersebut diperbarui dengan arahan pemilik. File suite lama
tidak diubah dalam slice ini, dan Codex tidak menjalankannya.
